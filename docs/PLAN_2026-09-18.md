  ```json
  {
  ```

### W3 · `read_symbol`（细粒度定位） `¥0` `P1`

**做什么**
新增工具（**不是** `read_file` 的字符串参数）：

```
read_symbol(path, symbol, occurrence=0, context_lines=N)
→ {start_line, end_line, symbol, kind, source, candidates?}
```

- `symbol` 用 qualified name（如 `GroupDefault.get_override_key`）；
- **歧义时返回候选列表并拒绝猜测**——与 `replace_text` 的「必须唯一匹配」同一原则；
- 必须处理：重名函数、方法与顶层函数同名、overload、嵌套定义、装饰器 + 多行签名。

**为什么**
B 类的 4 次运行读同一个文件的重叠区间达 6 段、覆盖近 700 行
（例：hydra-1791 t2 读 `default_element.py` 的 `1-50 / 50-330 / 330-470 / 470-620 / 527-700 / 104-330`）。
**这是「逐页翻书找一句话」**。现有 `_python_chunks` 只有顶层裸 symbol，因此实现采用了
独立的递归 AST qualified-symbol 索引，而不是复用一个并不存在的完整索引。

**Codex 已指出的三个风险（已纳入设计）**
1. 朴素字符串查找会撞上重名/方法/overload/嵌套 → 改用 AST/`CodeChunk` 驱动；
2. 无 occurrence 参数无法消歧 → 已加入；
3. 返回必须带精确行范围与**有界**上下文 → 已纳入签名。

**验收**
- 对 hydra / pydantic 中已知重名的 symbol 能正确区分（用已有快照离线验证，不跑模型）；
- fake-client 单测覆盖：唯一命中 / 多候选 / 不存在 / 嵌套。

### E1 · 无进展干预的对照实验

**目的**：验证 W5 的干预能否把 B 类从「只读不写」推进到「提交一次修改」。

> ⚠️ 注意：**主要终点不是通过率**，而是「**是否产生了任何编辑**」。

**设计**

| 组 | 任务 | 协议 | 目的 |
|---|---|---|---|
| **目标对照** | 预先固定一个 B 类任务 | 同一 v2 协议下 W5 **off / on** 各一次 | 只改变 W5 开关 |

干预是新变量。**如果它让原本能过的任务变差，那收益是假的。**
DVC-4185 的历史首次编辑最晚（step 8），最接近阈值；DVC-4124 是便宜的早收敛检查。
回归组只能发现单例退化，不能证明总体无回归。

**成本估算**（按历史单价）
- 回归 smoke：约 ¥0.49 + ¥0.11 ≈ **¥0.60**
- 目标 off/on：按历史单价约 **¥1.1–1.2**
- **合计约 ¥1.7–1.8**；仅是历史估算，不是预算承诺

**前置条件（缺一不可）**
1. W1、W2、W8 完成（否则结果无法归因）；

## 7. 本计划与既有路线图的关系

`CLAUDE_CODE_HANDOFF.md` §6 把 **Reviewer + Revision** 列为最高优先级。
本计划**不推翻它，只调整顺序**：

```
原顺序：Reviewer + Reviser  →  （之后再看别的）
新顺序：账本可信 → B 类干预 → 冻结协议 → 一次对照实验 → Reviewer + Reviser
```

理由：**Reviewer 只能审查已经形成的补丁**，而当前 4 条运行连补丁都没有产生。
先把「不提交」这个最高频失败压低，Reviewer 才有对象可审。

**Reviewer 仍是 P2，没有被取消。**
